# Results and how to reproduce them

## Setup

- `sim/trustsim.py` is a statistical simulator, with no AI in the loop. Each of the 10,000 participants is
  a few numbers: skill, diligence, honest/attacker/colluder, online or offline. Time step: 1 hour.
- The environment is frozen for every design:
  - presence: about 17 % online, about 20 days of membership, with newcomers replacing leavers;
  - population: 1 % lone attackers, 1 % colluders in rings of 5, 20 % careless reviewers, 2 % long-standing
    members at the start;
  - durations: 4-16 h to write a change, 1-2 h to review, 2-4 h to audit;
  - detection: one review catches a backdoor with probability `diligence x skill x visibility`, and an
    audit with 1.5x that. Subtle backdoors in low-risk code have visibility 0.17-0.35;
  - attacker behaviour: backdoors prefer low-risk code, and 30 % are flagged by tooling.
- **Fair attacker trigger.** In the evaluation, attackers start planting backdoors a fixed delay after
  joining: eager 0, standard 3, patient 15 days. A design's rules cannot change that delay. Without this,
  designs that slow down trust growth look safer only because attacks start later.
- **Shipped backdoors.** A merged backdoor counts as shipped with soak *d* if it was not found within *d*
  days of merging. A release takes only changes older than *d*.
- 90 days, 5 seeds, mean values.

## What the measurements taught

- **Safety tracks the number of independent looks.** A review catches a subtle backdoor about 15 % of the
  time and an audit about 26 %. Rules that cannot see who is malicious can only trade throughput for
  checking hours, or make each hour count more.
- **Calibration ranking makes hours count more.** With reviews sent to the members who catch canaries best,
  the average catch rate goes from 0.53 to 0.65, and careless reviewers do 4 % of reviews instead of 19 %.
  It only works with jury duty: with review credits, ranked reviewers starved everyone else (1,805
  merged/day).
- **The soak window** is where post-merge checks pay off. Going from shipping on merge to a 14-day soak
  divides shipped backdoors by 2-3 in every design.
- **Spare reviewers** fix latency. Merge time is driven by reviewers going offline mid-review, not by
  queues.
- **Fixed high trust thresholds starve audits.** With churn, almost nobody reaches them, so the baseline's
  audits never ran.
- **Full contagion** (banning everyone who approved a backdoor) bans honest reviewers with no security gain.
- **Did not help, within noise:** more reviewers on low-risk code at the same cost, targeting checks at
  changes approved by low-ranked reviewers, extra audits on young accounts, gentler or stricter canary
  scoring.

## Reproduce

```sh
cd sim/eval
python crosseval.py 90 5        # about 15 minutes on 12 cores; writes results_90d.json
python report.py                # prints the table
python ../trustsim.py --seeds 5 # the original scenarios and ablations, 30 days
```

Each `sim/designs/agentN/` holds the designer's own `DESIGN.md`, written before they saw the simulator, and
their simulator copy. `sim/designs/synth/` is the synthesis (scenario `synth`).
